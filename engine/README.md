# Rust sidecar status

Tier C is active. `ringside-engine` is a small Rust NDJSON stdio sidecar scaffold: `cargo test --manifest-path engine/Cargo.toml` and `cargo run --manifest-path engine/Cargo.toml -- health` check its protocol. It reports `available: false` and refuses every swap/escrow method. The swap and escrow proof orchestration and devnet programs have not been built or deployed. MCP advertises their tool schemas so clients can discover the planned coverage, but calls return `ENGINE_UNAVAILABLE` even if an external binary path is set. Spend policy integration must be completed before the bridge can execute those operations. Do not claim these operations work on devnet or localnet.

The source orchestration references are in the `vendor/zolana-examples` submodule. The example programs use insecure deterministic proving keys and are suitable only for devnet test funds. The PRD's escrow contract allows creator withdrawal after a timelock; it has no trustless beneficiary release. `escrow_release` is intended as withdrawal followed by a separate private transfer.

Rust 1.99.0 and the upstream Zolana CLI were installed in this workspace. Go 1.27.1+ and the Agave CLI are still absent. Building the upstream prover and programs requires those tools as described in the PRD. A deployment must use new program keypairs and recompile `declare_id!`; the upstream swap and escrow program IDs are not deployed on devnet.
