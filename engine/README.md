# Rust sidecar status

The Ringside engine remains Tier C. `ringside-engine` is a Rust NDJSON stdio scaffold: `cargo test --manifest-path engine/Cargo.toml` and `cargo run --manifest-path engine/Cargo.toml -- health` check its protocol. It reports `available: false` and refuses every swap/escrow method. MCP advertises their schemas, but calls return `ENGINE_UNAVAILABLE`. Spend policy integration and proof orchestration must be completed before the bridge can execute those operations.

**Localnet spike (Oct 9):** The upstream `zolana-examples` v0.4 programs compiled with Agave 4.0.2 and loaded as executable programs on Surfpool. Go 1.27.1 generated the example test proofs. The upstream `make_and_take_swap_inline` and `escrow_then_withdraw` tests both passed against their own `FixtureLocalnet`, Photon, and prover. This verifies the protocol path, not a Ringside MCP tool. The test harness uses fixed public fixture keys and upstream example program IDs. A first escrow start hit a Photon SQLite migration error; a fresh rerun passed without the experimental local Photon source patch. The patch was not used in either successful transaction run.

The source orchestration references are in the `vendor/zolana-examples` submodule. The example programs use insecure deterministic proving keys and are suitable only for devnet test funds. The PRD's escrow contract allows creator withdrawal after a timelock; it has no trustless beneficiary release. `escrow_release` is intended as withdrawal followed by a separate private transfer.

Rust 1.99.0, Go 1.27.1, Agave 4.0.2, and the Zolana v0.4 release CLI are installed in this workspace outside Git. A Ringside deployment must use new program keypairs and recompile `declare_id!`; the upstream swap and escrow program IDs have not been deployed on devnet. The localnet spike exceeded the PRD's 90-minute M3 timebox, so engine integration remains explicitly open rather than enabling unprotected spending.
